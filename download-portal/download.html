Install CelikPanel.

One command on a clean server. It downloads the latest signed release, checks it, and installs the panel and its agent. The server needs no Go, Node.js or Git.

Current release @@CP_RELEASE_VERSION@@ · @@CP_RELEASE_DATE_EN@@ · Linux amd64

  1. Create a free account and take a licence for the server. Each server has its own.
  2. Prepare a clean server with one of the supported systems.
  3. Run the command in the server’s root terminal.
  4. Sign in at the address the installer shows. The setup wizard asks for your domain, one or two servers, their roles and where DNS lives.

Install command

timedatectl set-ntp true
curl -fL --proto '=https' -o celikpanel-install.sh https://celikpanel.net/get.sh &&
sh celikpanel-install.sh

Run the three lines together in the server’s root terminal. The first turns on clock synchronisation, because certificates need the right time. If the installation stops, run the same command again.

What each system offers, and how its updates work

The setup wizard finishes the job.

On your first sign-in the wizard asks for your main domain, one or two servers, their roles and where DNS lives. Every step says what it installs; if something has to wait, the screen says why and what to do next.

Where DNS lives

Your own pair
Two servers keep your domain’s DNS together: one is the main DNS server, the other the backup. You choose which one is the main.
An outside DNS provider
If you use a provider such as Cloudflare, no DNS software is installed. The panel lists the records to add and shows what the internet answers for each.
One server
One server keeps its own DNS, with both name server names on it.

Setting up two servers

  1. Install the panel on both servers, each with its own licence.
  2. Go through the wizard on the first server. Choose mail on one server only.
  3. When its setup starts, choose “Create a join code”. The code is shown once and is valid for 24 hours.
  4. In the second server’s panel choose “Join the first server with a code” and enter the first server’s IP address and the code. The shared answers come from the first server.
  5. With your own DNS, when the registrar card says so, set the name servers (NS) and their IP records (glue) at your domain registrar. The card checks them by itself.

How CelikPanel changes your server.

With one rule taken from railway signalling: once a route is set, every route that conflicts with it is locked, so the wrong lever cannot be pulled.

  1. Preview

    Before changing anything, the panel asks the server whether the change can be made. The answer is either a list of blockers or a single-use approval. If something blocks it, nothing changes.

  2. Commit

    Only that approval makes the change. While it runs, the server holds one right to change; a second change waits its turn instead of stacking on top.

  3. Record

    Every privileged change is written to a durable record with its outcome. If the power fails, the panel finds the unfinished work and finishes or reverses it; it never shows a half-done change as a success.

Signed, checked, and yours to inspect.

You do not have to take the download on trust. Each step can be checked.

  • Every release package is signed. The installer checks the signature and the package checksum before it installs anything.
  • Every release’s notes name its commit and say what was tried in the lab, and what was not.
  • The panel and its agent are two separate services. The web-facing panel runs without root; only the local agent may change the system.
  • Your first administrator’s password is chosen on your server and is never sent to this website.

Already installed?

Update from inside your panel, under Settings, CelikPanel updates. Only you start it; nothing installs by itself.
