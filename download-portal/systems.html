Supported operating systems

CelikPanel runs on Linux servers. What is supported today, what each system offers, and how its updates work.

1

The list

Dates are the distributions’ own security support dates.

Table 1 · Operating systems (distribution dates checked on 24 October 2026)

Tested: every release candidate is run on it before it is published. Supported: CelikPanel installs and runs on it; release candidates are not run on it. Arch Linux is supported as it is today. The release package is built for amd64.

Other systems are not supported yet; support for more systems is planned. Red Hat family systems (RHEL, AlmaLinux, Rocky Linux 9) are recognised, and the installer refuses them for now. A system not in this table has not been checked.

2

Systems with apt

Debian and Ubuntu. Packages come from the distribution.

Table 2 · What the apt systems offer
What is offeredCelikPanel’s components from the distribution’s own packages. Where a newer version is wanted, a vendor repository (for PHP or PostgreSQL, for example) is offered only as a deliberate choice.
What is not offeredApache and Exim, on any system: their integration is not finished, so use Nginx and Postfix. Versions differ by release: Debian 13 ships PHP 8.4 and PostgreSQL 17, Ubuntu 24.04 ships PHP 8.3 and PostgreSQL 16. The panel shows what your release offers.
How updates workFixes come from the distribution’s security and update archives. The system’s own unattended-upgrades installs them every day by itself, or you install them by hand; you choose in the panel under Security. The choice is one apt file, /etc/apt/apt.conf.d/20auto-upgrades, so it keeps working while CelikPanel is stopped. The panel never restarts the server by itself.
New major versionsA new major version, such as PostgreSQL 17 after 16 or PHP 8.5 after 8.4, is a separate program and not an update. Updates fix the version you have; you move to a new major version yourself, when you decide.
3

Systems with pacman

Arch Linux, a rolling release. Only official Arch packages are used.

Table 3 · What Arch Linux offers
What is offeredThe server roles with official Arch packages: web, PHP, MariaDB, PostgreSQL, mail, certificates, the firewall and backups. Valkey is offered where other systems offer Redis.
What is not offered, and why
  • phpPgAdmin and SpamAssassin: Arch’s official repositories have no working package (only the AUR does, which CelikPanel does not use). Manage PostgreSQL with psql, and use Rspamd as the spam filter.
  • Redis: Arch ships the compatible Valkey instead, so Valkey is offered.
  • Apache and Exim: not offered yet on any system. Use Nginx and Postfix.
  • Switching an existing DNS server to PowerDNS: on Arch, PowerDNS is installed only on a server with no DNS software.
  • Automatic upgrades: CelikPanel schedules none on Arch.
How updates workEvery update is a full upgrade that you run on the server: read archlinux.org/news first, then run sudo pacman -Syu, then check failed units, nginx -t, PHP-FPM and the mail services, and restart the server if the kernel changed. The panel lists these steps; it never runs the upgrade for you.
Before a big upgradeA full upgrade can move Arch’s php and PostgreSQL packages to a new major version. Test your sites after the upgrade, or on a copy of the server first.
4

Independent of the panel

CelikPanel operates your server; it does not own it. On every system above, sites, mail, DNS, databases, scheduled tasks and site certificate renewal keep running while the panel is stopped.
