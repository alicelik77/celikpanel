Supported operating systems.

CelikPanel installs on Debian, Ubuntu and Arch Linux. This page says what is offered on each, what is not and why, and how updates work, so you can choose before you install.

The list

Tested means every release candidate of CelikPanel runs on that system before it is published. Supported means CelikPanel installs and runs on it, but release candidates are not run on it. Dates are the distributions’ own support dates, checked on 24 October 2026.

Debian and Ubuntu

What is offered

All of CelikPanel’s components: web server and PHP, MariaDB and PostgreSQL, mail with Rspamd, DNS with BIND or PowerDNS, certificates, the firewall, backups and the security tools. Packages come from the distribution. Where a newer version is wanted, the panel offers a vendor repository only as a deliberate, confined, tracked choice.

What is not offered

Apache, Exim and FTP (vsftpd) are not offered yet, on any system: their integration is not finished, so use Nginx and Postfix. Everything else in the catalogue is offered. Versions differ by release: for example Debian 13 ships PHP 8.4 and PostgreSQL 17, Ubuntu 24.04 ships PHP 8.3 and PostgreSQL 16. The panel shows what your release offers.

How updates work

Fixes come from the distribution’s security and update archives. The system’s own tool, unattended-upgrades, can install them every day by itself, or you install them by hand. You choose in the panel under Security, Security updates. The choice is one apt file on your server, so it keeps working while CelikPanel is stopped. If you edit that file yourself, the panel notices and asks before it replaces your text. The panel never restarts the server by itself.

New major versions

A new major version of a program, such as PostgreSQL 17 after 16 or PHP 8.5 after 8.4, is a separate program and not an update. Updates fix the version you have. You move to a new major version yourself, when you decide.

Arch Linux

What is offered

The server roles work with official Arch packages only: web, PHP, MariaDB, PostgreSQL, mail, certificates, the firewall and backups. PowerDNS comes from Arch’s extra repository as a first install. Valkey is offered where other systems offer Redis.

What is not offered, and why

  • phpPgAdmin and SpamAssassin: Arch’s official repositories carry no working package (only the AUR does, and CelikPanel does not use it). Manage PostgreSQL with psql, and use Rspamd as the spam filter.
  • Redis: Arch ships the compatible Valkey instead, so Valkey is offered.
  • Apache, Exim and FTP (vsftpd): not offered yet on any system. Use Nginx and Postfix.
  • Switching an existing BIND server to PowerDNS: PowerDNS is offered as a first install only.
  • Automatic upgrades: Arch has no security-only updates, and an unattended full upgrade can stop your services.

How updates work

Arch is a rolling release. An update is always a full upgrade that you run on the server: read archlinux.org/news first, then run sudo pacman -Syu, then check failed units, nginx -t, PHP-FPM and the mail services, and restart the server if the kernel changed. The panel counts what is waiting and shows these steps; it never runs the upgrade for you.

Before a big upgrade

A full upgrade can move Arch’s php package to a new major version, and PostgreSQL to a new major version whose data directory must then be upgraded before the server starts again. Test your sites after the upgrade, or on a copy of the server first.

Your server stays yours.

CelikPanel operates your server; it does not own it. Sites, mail, DNS, databases, scheduled jobs and site certificate renewal keep running while the panel is stopped, on every system above.
