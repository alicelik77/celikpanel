Report a problem

How to report today, what to include, and what happens next.

Table 2 · Reporting a problem
A security problemReport it privately, never in a public issue: private security report on GitHub
Any other problemOpen a report in our feedback repository on GitHub. Write nothing there that you would not publish. Report a bug on GitHub
What to includeThe CelikPanel version, the operating system, what you pressed, and what the screen said.
What never to sendPasswords, keys, tokens or anyone’s personal data.
What happens nextWhen we accept a report, it gets a number on this page, then its state, and once fixed the version that fixed it.
Reporting formThere is no reporting form in the celikpanel.net account yet; report as above.

What the states mean

Table 3 · States of a case
Reported, being looked atWe have the report and are finding out what happens and why.
Accepted, will be fixedIt is a defect and a release will fix it; the case says what to do until then.
FixedThe named release fixed it; update to it from the panel’s own update screen.
Not a defectThe panel works as intended; the case says why.
