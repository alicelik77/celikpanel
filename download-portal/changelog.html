Changelog

What each release changed, in a few plain lines, newest first. Each release’s full notes also say what was tried in the lab and what was not.

2026-11-25

v0.1.0-alpha.148

Changes in v0.1.0-alpha.148
KindChangeCase
SecurityEach site’s programs (uploaded programs, Python apps, the Node.js application, service apps, and their install, build and deploy steps) run inside one memory, process and processor limit of their own, so together they can no longer take the whole server from the other customers; a site’s PHP keeps its own limits and its scheduled tasks are not inside them.CP-2026-21
SecurityThe panel’s sign-in cookies carry names a browser keeps only for the panel’s own host name, so a website on another host name under the same domain can no longer set, shadow or replace the panel’s sign-in; the database tools reached through the panel’s address no longer receive it.CP-2026-22
SecuritySigning out after “Log in as” also ends the administrator’s own session in that browser, so nobody who signs in there afterwards can return to it; when a “Log in as” session ends any other way, the browser no longer keeps the administrator’s sign-in.CP-2026-23
NewPlans, reseller plans and accounts set a site’s memory, processes and processor; without a setting a site gets 512 processes, two processor cores and the smaller of 3072 MB and 75 % of the server’s memory. Lowering a limit below what a site uses lists that site first.—
Known limitPrograms that ran before the update stay outside their site’s limits until the administrator moves the site; the move restarts each of its running programs once.—
Known limitA site’s PHP and its scheduled tasks are outside the site’s limits; PHP keeps its own limits per site.—
Known limitResellers, customers and team members who were signed in at the time of the update sign in once. Every service on the panel’s own host name shares its cookies, whatever the port, so that host name should serve the panel alone.—

2026-11-24

v0.1.0-alpha.147

Changes in v0.1.0-alpha.147
KindChangeCase
SecurityphpMyAdmin, phpPgAdmin and webmail run under system accounts of their own instead of the web server’s shared account, which can read every site; webmail needs a file system with access-control lists for this.CP-2026-18
SecuritySite accounts can no longer schedule jobs with the system’s at; an at.allow the owner wrote is kept and the site accounts it names are shown to the administrator.CP-2026-19
SecurityThe distribution’s shared PHP pool, which runs as the web server’s account, is switched off where nothing uses it; where something still uses it, it is kept and Problems now names what.CP-2026-20
FixedA longer change no longer stays “in progress” when the panel loses touch with its agent for a moment: the panel reads what the server did and records the result by itself.CP-2026-17
NewCrontab lines a site adds outside the panel are marked on its Scheduled tasks list; they can be deleted, and the administrator may keep them.—
Known limitOn Arch Linux the tools stay on the web server’s account and the PHP pool is not switched off; at and the site crontabs are handled on every system.—
Known limitA site account can still add lines to its own crontab; they are shown, can be deleted and, by the administrator, kept.—

v0.1.0-alpha.145

Changes in v0.1.0-alpha.145
KindChangeCase
SecurityWebmail’s local door on the server answers only CelikPanel’s own checks; before, any account on the server could read Roundcube’s files through it and run plugin scripts.CP-2026-16
FixedWebmail can send mail: it switches encryption on and signs in with the mailbox’s own address and password.CP-2026-12
FixedAn alias’s “waiting to be published” ends when its zone’s change is published, not an hour later.CP-2026-13
FixedThe window of a PostgreSQL close or its undo ends with a title that says the outcome.CP-2026-14
Known limitA longer change can stay “in progress” on the panel after it has finished on the server; after about five minutes, run sudo systemctl restart celikpanel-panel. The panel then records what was really done: a webmail update is only read and not run again; an interrupted install is resumed and completed on the server.CP-2026-17
Known limitThe Webmail card still offers Repair while webmail cannot send; Repair does not correct the configuration, and the step is in Problems now.—
Known limitNothing of this release was tried on Arch Linux in its lab.—

v0.1.0-alpha.142

Changes in v0.1.0-alpha.142
KindChangeCase
